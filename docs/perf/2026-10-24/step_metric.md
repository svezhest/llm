# Пункт 0: «~200 мс на шаг» — артефакт лога (2026-10-24)

Гипотеза из `deepinfer_ideas.md` подтверждена. В строке `batch:` поля `rows`/`prefilling` — снимок
в момент записи, а `steps/s` — за 10-секундное окно, в котором проходили слэбы префилла по 4–9 с.
Поэтому «rows=6 prefilling=n → 5.08 шага/с» в `stats_6proc_steady.txt` не говорило о времени шага.

Новая метрика (коммит 9b79624): `step_ms` = стена декод-тиков / шаги окна (step-ahead делает её
временем шага на GPU), `gbps` = байты, которые шаг обязан прочитать (`_step_bytes`: веса без
embedding + KV всех строк + 2 × GDN-состояние), / стена; `decode_s` / `prefill_s` — разбивка окна.

Прогон: replay AppWorld (`scripts/perf/agentic/replay.py --own-replies --ignore-eos off`),
8 эпизодов × 10 мин, 9B, `QWEN_PROMPT_CACHE_GB=6 QWEN_BATCH_RESERVE_TOKENS=1024
QWEN_PROMPT_CACHE_REPLY=1`, MAX_BATCH 16. Машина под давлением памяти (браузер пользователя +
6 агентов с CPU-тестами; своп 5.4 → 9.2 GB, CMPRS воркера 6.7 GB) — абсолютные числа шумные.
Сырые: `raw/item0_replay.{txt,json}`, `raw/item0_batch_lines.log`.

- Шаг декода на агентной нагрузке — 36–60 мс при 2–7 строках (контекст ~10K), в 3–5 раз
  меньше «200 мс». Медленного декода нет.
- **81 % занятого времени планировщика — префилл, 19 % — декод.** Узкое место пропускной
  способности AppWorld — префилл и промахи кэша (MISS/вытеснения), не шаг декода. Приоритет:
  дисковый уровень кэша (п. 2), полоса коротких префиллов (п. 4); декод-пункты (1, cascade) —
  ради детерминизма и памяти, не ради req/min.
- GB/s падает с 300 (B=1) до ~210 (B ≥ 4): per-row decode attention на ~10K контекста ≈ 2×
  своего bandwidth floor (известно, `docs/perf/2026-10-12/step_profile.md`) + mrqmm 3..8 строк
  ~1.07× qmv. За прогон step_ms дрейфовал вверх (~38 → ~58 мс при 6–7 строках): троттлинг / своп.
- Итог прогона: 22.3 запроса/мин, хиты 94 %, латентность p50 14.7 с (очередь 36 %, ttft 15 %,
  декод 49 % латентности запроса — декод длинный по стене из-за префиллов между шагами).
